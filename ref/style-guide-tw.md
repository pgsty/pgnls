# PostgreSQL NLS 繁體中文翻譯風格指南（nls-v3-tw）

**適用範圍**：PostgreSQL `zh_TW` 全部元件的 `*.po` 訊息（錯誤、詳情、提示、日誌、進度、`--help` 說明文字、標籤表、psql 元命令輸出），以及此後各版本的同類訊息。

**與簡體指南的關係**：本指南與 [`style-guide.md`](style-guide.md)（nls-v3）同源。結構層的規則（R1–R14 的訊息類型、忠實、標點、空格、對齊、佔位符、空白契約、複數、變更紀律）沿用簡體版已驗證的體系；**術語層與用字層全部按繁體中文（台灣）重新校準**，校準基準是官方 PostgreSQL 原始碼樹既有的 zh_TW 譯文（見 R0.5）。兩者衝突時，以本指南為準。

**目標**：準確 > 一致 > 流暢 > 本土化潤飾。訊息是運維現場讀的東西：一眼看懂出了什麼問題、涉及哪個物件、要做什麼；能複製到 psql、shell、grep 和 issue 裡繼續用。

**優先級**：技術正確（含源碼語境） > 本指南條款 > [`phrasebook-tw.tsv`](phrasebook-tw.tsv)（`status=decided`） > [`glossary-tw.tsv`](glossary-tw.tsv) > 官方既有 zh_TW 譯文（對齊義務見 R0.5） > 同元件既有穩定譯法 > 個人偏好。發現術語表有誤，核對英文後修正並記錄，不在譯文裡私自繞開。

條款編號 R0–R14 供人和 agent 引用；R0 是繁體中文專屬的校準層，其餘條款與簡體版一一對應。

## R0 繁體中文校準層（本指南專屬）

繁體中文不是「簡體中文換字形」。以下四個小節是 zh_CN 語料不能直接字符轉換的全部原因，也是本指南與簡體版的大部分差異所在。

### R0.1 用字：台灣正體

- 用字遵循台灣通行正體：`為`（不用 `爲`）、`裡`（不用 `裏`）、`啟用`、`雜湊`、`資訊`、`記憶體`。以 OpenCC `s2twp` 的字形為基準，不用 `s2t`（會產生 `爲`、`裏` 這類非台灣用字）。
- `台/臺` 用 `台`（官方譯文如此）；`群` 不作 `羣`。
- `計畫`（plan 名詞，如 執行計畫）與 `計劃`（動詞）依台灣慣用取 `計畫`；`字首/字尾`（prefix/suffix）不用 `前綴/後綴`；`座標` 不作 `坐標`。
- 一簡多繁的取捨由詞語決定，不由單字決定：`之後`、`複製`、`恢復/復原`、`關係`、`系統`、`衝突`。禁止直接逐字轉換的偽影，常見者列於 R0.4 禁字表。

### R0.3 行／列／筆：不可字符映射的最大單項

簡體 `行`(row)／`列`(column) 在繁體中反轉且另有計數用詞：

| zh_CN 語境 | zh_TW | 例 |
|:---|:---|:---|
| row（資料行） | **資料列**（簡稱 列） | `current row` → 目前資料列 |
| row 計數 | **筆** | `(1 row)` / `(%lu rows)` → `(1 筆資料)` / `(%lu 筆資料)`（跟隨官方 psql 譯文，計數括號用半形） |
| column | **欄／欄位** | `index column` → 索引欄位；禁止 MS 式 資料行 |
| field | 欄位（與 column 同詞） | |
| line（行號、命令列） | **行／列**：`line 5` → 第 5 行（跟隨 `行號` 慣用）；`command line` → 命令列；`new line` → 新行 | 逐條判斷，不得批量替換 |

### R0.4 簡→繁轉換管線（批量起草用）

存量 zh_CN 語料可以用管線起草 zh_TW，但**管線產物是草稿**，須按 R13 紀律逐條審校後才能入庫。管線本身必須按此順序：

1. **術語預替換**：先套用 `glossary-tw.tsv` 的 zh_CN→zh_TW 映射（長詞優先），這一步必須先於 OpenCC，否則交叉對（進程→行程 與 程序→程式；文件→檔案 與 文檔→文件）會互相污染。
2. **字符轉換**：OpenCC `s2twp`（殘差部分）。不要用 `s2t`／`s2hk`。
3. **偽影後修**：轉換器會產生系統性錯詞，逐項替換。禁字表（出現即錯）：

   | 偽影 | 應為 | | 偽影 | 應為 |
   |:---|:---|---|:---|:---|
   | 運算符 | 運算子 | | 排序規則 | 定序 |
   | 歸檔 | 封存 | | 死鎖 | 死結 |
   | 遊標 | 游標 | | 保存點 | 儲存點 |
   | 所有者 | 擁有者 | | 主頁 | 首頁 |
   | 集群／集簇 | 叢集 | | 外部表 | 外部資料表 |
   | 使用者對應／對映 | 使用者映射 | | 許可權 | 權限 |
   | 引數（parameter 語境） | 參數 | | 後臺 | 背景 |
   | 連線字串 | 連接字串 | | 資訊（message 語境） | 訊息 |
   | 高速緩存 | 快取 | | 插槽 | 槽 |
   | 退出 | 結束 | | 運運算元／演演算法 | 運算子／演算法 |

4. **計數改寫**：`%d 行`（row 計數）→ `%d 筆`；`%d 列`（column 計數）→ `%d 個欄位`。
5. **閘門**：`msgfmt --check --check-format`、佔位符恆等、`msgcmp` 與英文模板對齊、禁字表掃描、簡體殘字掃描（s2t 會變而 t2s 不變的字）。

兩條硬約束（2026-09-18 對抗性審查結論;本節以代碼域引用的簡體原詞按原樣保留,它們正是危險源本身）：

- **只能單遍同時匹配，禁止順序 sed 鏈**。CN→TW 對照存在目標串包含另一源串的鏈（`過程語言→程序語言` ⊕ `程序→程式`、`分配→配置` ⊕ `配置→組態`、`倒排列表→反向列表` ⊕ `列表→清單` 等 6 組），順序應用必毀。管線必須用「最長優先、一次掃描、命中區段保護」的引擎（`tmp/build_tw_glossary.py` 的實現）。
- **單字詞條不是字符串替換規則**。`表→資料表`、`行→資料列`、`列→欄位`、`位→位元`、`块→區塊`、`堆→堆積`、`頁→頁`、`锁→鎖定` 這些行只在「翻譯對應英文術語」時成立；對語料盲替換會把 `表示`(×83)、`模块`(×15)、`進行|類型` 之類複合詞毀掉（實測結論）。引擎已改為複合詞規則 + 跨詞界守衛（`分区表` 不搶 `分区表达式`、`行类型` 不搶 `进行类型`），消息級轉換必須走該引擎，不得手抄詞表做 sed。

### R0.5 與官方既有 zh_TW 譯文的對齊義務

官方原始碼樹已有五個元件的 zh_TW 譯文（psql 1,309 條、pg_dump 514、initdb 189、pg_ctl 154、libpq 287；backend `postgres.po` 官方**尚無** zh_TW）：

- 同一 `msgid` 官方已譯者，**以官方譯文為基準對齊**，我方差異記入報告回饋上游（pgsql-translators），不雙軌、不私改。
- 官方自身不一致處，我方按多數與合理性取捨並記錄：`行程`(23) 勝 `程序`(process 語境 14)；`命令`(58) 勝 `指令`(16)；`元組` 保留不譯；`commit` 譯 `提交`（不取 MS 的 認可）；`unexpected` 譯 `非預期`；`signal` 譯 `信號`（不取 訊號）；`shutdown` 譯 `停止`（不取 關機）；`promote` 譯 `升級`；`locale` 譯 `區域`；`schema`／`socket` 保留原文。
- 標點節奏與官方相容：官方 zh_TW 亦為半角冒號為主（五檔合併實測 4,278:15）、無 `「」`、句號用 `。`。R4 的兩層標點體系直接沿用。

## R1 訊息類型決定語氣與句末標點

主訊息小寫開頭、不加句號、儘量一行；詳情和提示是完整句子。中文必須保持這套分工，因為用戶端（psql、pgAdmin、日誌系統）按類型分別排版。

| 類型 | 中文處理 |
|---|---|
| 主訊息 `errmsg` | 短句，**不加句號**；不擴寫成完整敘述 |
| 詳情 / 提示 | 完整句，以 **`。`** 結尾；一句英文對應一句中文 |
| 上下文 `errcontext` | 片段，不加句號 |
| 日誌 / 進度 | 進行中「正在…」，已完成「已…」；不用「了」表示狀態 |
| 說明文字 | R6、R12 |
| 標籤表 | R4.2、R6.2 |
| 嚴重級別標籤 | R9.2：`錯誤:  ` / `警告:  `，半形冒號加兩個空格 |

- R1.1 英文以 `.` 結尾 ↔ 中文以 `。` 結尾；英文無句號 ↔ 中文無句號；`:`、`...`、`?` 對應保留（`：`、`...`、`？`）。
- R1.2 不把 DETAIL 的事實改寫成建議，不給 HINT 增加英文沒有的操作步驟，不加「請」「您」除非英文有 `please`/`you`。
- R1.3 語氣專業、乾練：不用驚嘆號，不用口語（「太多」→「過多」），不用文學化表達。

## R2 忠實：語義不增不減

- R2.1 保留否定範圍、條件、因果、先後順序、數量、執行主體、參數歸屬。`cannot X because Y` → 「無法 X，因為 Y」。
- R2.2 保留不確定措辭：`may`/`might`/`possibly`/`probably` → 「可能」／「也許」。
- R2.3 `expected X, got/found Y` → 「預期為 X，實際為 Y」；多組數量全部保留。
- R2.4 同一訊息多個調用點共用時，譯文對所有調用點都要成立。
- R2.5 拿不準的條目：給最保守、有依據的譯文並記錄疑問；不用英文原文或「待翻譯」充數。

## R3 術語與固定句式

### R3.1 名詞術語：以 `glossary-tw.tsv` 為準

術語表 638 條已按「官方 zh_TW 直接詞形證據（68 條）> 官方詞族推導（121 條）> 台灣微軟術語標準（281 條）> 專案裁定（48 條）> 字符轉換（119 條）」定稿；`官方推定` 表示構詞部件（如 行程、交易、檢查點）有官方出處，複合詞形本身未見於官方語料。消息中高頻、與簡體分歧最大的裁決：

| 英文 | 繁體 | 依據與邊界 |
|---|---|---|
| database cluster / cluster | **資料庫叢集 / 叢集** | 官方用 叢集；`CLUSTER` 命令原樣，作為動作是「叢集化」 |
| standby / standby mode / hot standby | **待命伺服器 / 待機模式 / 熱備援** | 官方 pg_dump／pg_ctl／libpq 用語；冷備→冷備援、溫備→溫備援同系列 |
| primary / master / secondary / slave | 主伺服器 / 主伺服器 / 待命伺服器 / 從屬伺服器 | 與 待命伺服器 對稱；`primary key` 是主索引鍵，逐條判斷短語 |
| replica / replication / replica identity | 複本 / 複寫 / **REPLICA IDENTITY（原文）** | 複寫 與 複製(copy)分立；`REPLICA IDENTITY` 關鍵字保留 |
| transaction / commit / savepoint | 交易 / 提交 / 儲存點 | 官方：提交目前的交易；commit 不取 MS 的 認可 |
| tuple / row / column / field | 元組 / 資料列 / 欄（欄位）/ 欄位 | 官方保留 元組；行/列反轉見 R0.3 |
| table / view / tablespace | 資料表 / 檢視 / **表空間** | 官方 psql 高頻；表空間 是固定詞，不隨 資料表 |
| schema | **schema（原文）** | 官方：`List of schemas` → `Schema 清單`；mode/pattern 語境才譯 模式 |
| socket | **socket（原文）** | 官方：`local socket` → `本機 socket` |
| process / procedure / program / thread | 行程 / 程序 / 程式 / 執行緒 | 三者分立，不得互換；daemon → 常駐程式 |
| extension / procedure language | 擴充模組 / 程序語言 | 官方用語；`file extension` → 副檔名 |
| foreign data wrapper / foreign server / foreign table / user mapping | 外部資料包裝器 / 外部伺服器 / 外部資料表 / 使用者映射 | 官方；FDW 縮寫保留 |
| collation / locale / encoding | 定序 / 區域 / 編碼 | 官方：`Locale Provider` → 區域提供者 |
| partitioning / partitioned table / partition key | **分割 / 分割資料表 / 分割索引鍵** | 官方 psql 主流：`declarative table partitioning` → 聲明式資料表分割；不取 MS 資料分割；pg_dump 另見 分區（官方內部不一致，取 psql 多數） |
| buffer / cache | 緩衝（區／集區）/ 快取 | buffer pool → 緩衝集區；buffer cache → 緩衝區快取 |
| memory / allocate | 記憶體 / 配置 | `out of memory` → 記憶體不足；allocate 語境 分配→配置 |
| latch / lock / deadlock | 閂鎖器 / 鎖定 / 死結 | latch 不取 s2t 偽影 鎖存器；spin lock → 自旋鎖 |
| operator / operator class | 運算子 / 運算子類別 | 不取 運算符／操作符 |
| expression / predicate / filter | 運算式 / 述詞 / 篩選 | regex 語境表示式（正規表示式）另論 |
| parser / planner / optimizer / executor | 解析器 / 規劃器 / 最佳化工具 / 執行器 | planner 不取 最佳化工具；MS 剖析器 不取 |
| plan / cost | 計畫 / 成本 | 執行計畫、成本估算；`計畫` 不作 `計劃` |
| archive / dump / restore / recovery | 封存 / 備份 / 還原 / 復原 | 官方 pg_dump 用語；dump 譯 備份 不取 傾印 |
| failover / switchover / promote | 容錯移轉 / 計畫性切換 / 升級 | 官方 pg_ctl：promote → 升級 |
| join 系列 | 聯結（等值聯結、巢狀迴圈聯結、合併聯結、雜湊聯結） | connection 是 連線；官方 connection string → 連接字串 為固定例外 |
| WAL / OID / LSN / TID / TOAST / VACUUM | 原樣 | 訊息裡是標識而非概念解釋 |
| vacuum / autovacuum | 清理 / 自動清理 | `VACUUM` 命令原樣；說明性 full vacuum 可寫 `VACUUM FULL` |
| worker | 工作行程（後台/並行/應用）；zstd 壓縮 worker → 工作執行緒 | 行程與執行緒按實體區分 |
| token | 符記（SQL 詞法）/ 權杖（OAuth） | MS 語彙基元 不取 |

- R3.3 同一英文在相同語境下只有一種譯法；同一句式在全部元件用同一模板：`could not open file "%s": %m` → `無法開啟檔案 "%s"：%m`。

### R3.6 相似訊息，相似譯法（訊息簇）

與簡體版機制相同：`nls_cluster.py` 按詞法相似度分簇（`exact`／`near`），簇內譯文必須一致或只差對應槽位。槽位詞表按繁體術語表更新：`open` → 開啟、`read` → 讀取、`file` → 檔案、`directory` → 目錄。

## R4 標點：標點屬於它所在的語言層

沿用簡體版 R4 的兩層體系（此體系與官方 zh_TW 的實測標點分佈相容，且更嚴格）：

1. **敘述層**——譯者寫的中文句子：用全形標點 `，``、``；``。``：``（）`。
2. **機器層**——原樣嵌入的標識符、值、SQL、路徑、`檔案:行號`、`host:port`、佔位符：保留半形。

**規則：敘述層用中文全形標點，機器層保留半形標點，引號一律 ASCII 雙引號。**

### R4.1 引號：ASCII 雙引號，永遠

`關係 "%s" 不存在`。不用 “ ” ‘ ’ 「 」。理由與簡體版相同：引號是值的邊界，不是句子的標點；輸出可直接粘回 SQL；`grep '"%s"'` 依賴 ASCII 引號。引號數量與英文一致；引號外側按 R5 留空格，內側不留。

### R4.2 冒號

| 場景 | 用 | 例 |
|---|---|---|
| 敘述句裡引出說明、值、原因 | **全形 `：`** | `無法開啟檔案 "%s"：%m`；`參數 %d：鍵不能為空` |
| 程式名前綴 `%s: ` | 半形，原樣含空格 | `%s: 無法存取目錄 "%s"：%m` |
| 嚴重級別 / 診斷欄位標籤 | 半形 + 與英文相同的空格數 | `錯誤:  %s`、`詳細資訊:  %s`、`第 %d 行:  ` |
| `檔案:行號`、`host:port`、`%u:%u` | 半形 | `pltcl.c:479` |
| 標籤對齊表 | 半形 + 空格對齊 | `最新檢查點的 TimeLineID:        %u` |
| 引號內的字面量 | 原樣 | `預期為 "://"` |

### R4.3 括號

- 說明性括註屬於敘述層，用全形 `（）`，**即使裡面是機器值**：`交易 %u（紀元 %u）`、`%s（PID %d）`、`陣列大小超過允許的最大值（%zu）`。
- 語法括號屬於機器層，保留半形：`setlocale()`、`count(*)`、`[OPTION]...`。
- 判定方法：把括號連同內容刪掉，句子還成立，就是括註（全形）；刪掉就不再是那個 token，就是語法（半形）。
- 例外：row 計數 `(1 筆資料)` 跟隨官方 psql 用半形（見 R0.3）。

### R4.4 逗號、頓號、分號、句號、省略號

- 普通中文敘述用 `，` `、` `；` `。`。動作、物件類別和概念列舉用頓號：`啟用、停用或驗證`、`資料表、檢視和序列`。
- 準確的組態值、枚舉值、SQL 關鍵字、選項名、單位等 token 組成的清單，用 ASCII 逗號加一個空格：`允許的線型是 ascii, old-ascii 和 unicode`、`必須為 "fetch", "stream" 或 "none"`。
- 主機、使用者、資料庫、PID 等診斷屬性，保留 ASCII 邊界：`主機 "%s", 使用者 "%s", 資料庫 "%s", %s`。
- and、with、上下限與塊內位置等關係優先用連詞或重組表達：`%d 列和 %d 個欄位`、`至少 %d 個且至多 %d 個`、`區塊 %u 中位移 %u 處`。
- 省略號保留 ASCII `...`；`%%` 緊貼數字：`%d%%`。

### R4.5–R4.6 判定流程與對照示例

判定流程與簡體版 R4.5 相同（可複製片段→半形；格式分隔符→半形；技術值清單→ASCII 逗號；其餘中文句→全形，引號永遠 ASCII）。對照示例：

| ✗ | ✓ |
|---|---|
| `無法開啟檔案 "%s": %m` | `無法開啟檔案 "%s"：%m` |
| `無法識別的編碼：“%s”` | `無法識別的編碼："%s"` |
| `錯誤：第 %d 行` | `錯誤: 第 %d 行`（與英文 `Error: ` 空格數一致） |
| `由於 setsid（） 失敗` | `由於 setsid() 失敗` |
| `主機 "%s"、使用者 "%s"、%s` | `主機 "%s", 使用者 "%s", %s` |
| `重置後的首個日誌段：      %s` | `重設後的第一個日誌區段:        %s` |

## R5 空格

- R5.1 中文與英文單詞、數字、佔位符、ASCII 引號之間留**一個**半形空格：`第 %d 行`、`型別 int`、`檔案 "%s" 的`。
- R5.2 全形標點兩側不加空格；全形括號內側不加空格。
- R5.3 佔位符與量詞之間留空格（`%d 位元組`）；百分號緊貼（`%d%%`）。
- R5.4 提示符結尾的空格必須保留（`Enter new superuser password: ` → `輸入新的超級使用者密碼: `）。

## R6 終端對齊：按顯示寬度

終端裡一個漢字佔兩列。所有對齊按**顯示寬度**計算，不按字符數。

- R6.1 說明選項行：選項列原樣（含元變量 `FILENAME`、`NUM`）；說明列從與英文相同的顯示列開始；整行不超過 79 列。用法行元變量按慣例翻譯：`%s [OPTION]... [DBNAME]` → `%s [選項]... [資料庫名]`；`DATADIR` → 資料目錄、`SECS` → 秒數。
- R6.2 標籤對齊表（pg_controldata、pg_resetwal、initdb 摘要）：標籤後半形冒號，用空格把值補到同一顯示列；中文標籤比英文列寬還長時整表一起加寬。
- R6.3 `printf` 固定寬度片段（`%-20s`、`%5d`）保留修飾。

## R7 佔位符

- R7.1 與英文**完全一致**：類型、長度修飾、寬度、精度、標誌，數量一個不多一個不少。
- R7.2 調換語序用位置參數 `%1$s`、`%2$d`；一旦使用，所有消耗實參的佔位符都要編號。
- R7.3 `%m` 是 errno 文本，放在全形冒號後：`：%m`。
- R7.4 每條候選都要通過 `msgfmt --check --check-format`。

## R8 空白與換行契約

- R8.1 首尾空白、換行、制表符數量與英文一致（msgfmt 強制）。
- R8.2 中文不得比英文多換行。
- R8.3 結構性換行必須保留：選項行、標籤行、列表項、空行分段、示例。
- R8.4 純因行寬折行的句子可以合併（中文一行放得下時）。

## R9 不翻譯的內容

SQL 關鍵字與命令、GUC 參數名、選項名（`--jobs`）、函數與調用（`setlocale()`）、類型名（`integer`、`bytea`）、標識符、檔名、路徑、環境變數、協定名、SQLSTATE、信號名、`NULL`/`true`/`false`、`pg_*`、`postmaster`、`WAL`/`OID`/`LSN`/`TLI`/`XID`、`TOAST`、`portal`、`nonce`、psql 元命令一律原樣。**繁體版新增：`schema`、`socket`、`replica identity` 保留原文（官方 zh_TW 慣例，見 R0.5）。**

- R9.1 `VACUUM` / `CLUSTER` / `ANALYZE` 作為命令保留；作為動作說明分別是「清理」「叢集化」「分析」。
- R9.2 嚴重級別標籤半形冒號 + 兩個空格：`ERROR:  `→`錯誤:  `、`WARNING:  `→`警告:  `、`DETAIL:  `→`詳細資訊:  `、`HINT:  `→`提示:  `、`CONTEXT:  `→`上下文:  `、`LOG:  `→`日誌:  `、`NOTICE:  `→`注意:  `、`FATAL:  `→`致命錯誤:  `、`PANIC:  `→`嚴重錯誤:  `、`STATEMENT:  `→`敘述:  `。
- R9.3 選項行裡的元變量保留；用法行裡的元變量按 R6.1 翻譯。
- R9.4 psql `\h` 語法模板裡的小寫佔位符譯成中文（欄位條件約束、資料表名），大寫關鍵字原樣。

## R10 中文表達

- R10.1 短句，主謂賓清楚；一句英文對應一句中文。
- R10.2 少用「被」字句：`could not …` 一律「無法…」；能轉主動優先。
- R10.3 「未 / 尚未」表示還沒發生，「已」表示完成，「正在」表示進行中；不用「了」表達狀態。
- R10.4 數字寫法跟隨原文：英文用完整單詞表達的數量、序號，中文用漢字數字（`one` → 一、`first` → 第一、`two`/`both` → 兩）；英文本來寫成數字的保持數字（`1`、`4th`、`32-bit`、`LIMIT 1`）。漢字數字與漢字之間不留空格。不譯冠詞；不加「請」「您」除非英文有。
- R10.5 不做翻譯腔的直譯：重組語序以中文習慣為準。
- R10.6（繁體專屬）動詞與虛詞按 R0.2 對照表替換後重讀一遍全句：簡體直轉常留下「獲取」「訪問」「創建」「返回」「退出」「禁用」等非台灣用語，以及「信息」歧義（message→訊息，information→資訊）。

## R11 複數

- `Plural-Forms: nplurals=1; plural=0;`，只有 `msgstr[0]`，須同時覆蓋單複數：`%d row(s)` → `%d 筆`（計數語境）或 `%d 列`（指稱語境），不寫「一行」。
- `(1 row)` / `(%lu rows)` 跟隨官方 psql：`(1 筆資料)` / `(%lu 筆資料)`。

## R12 說明文字與共用字串

全部元件共享的相同英文，譯法必須完全相同（lint L11）。固定譯法：

| 英文 | 繁體 |
|---|---|
| `Usage:` / `Options:` / `Less commonly used options:` | `用法：` / `選項：` / `不常用選項：` |
| `Try "%s --help" for more information.` | `執行 "%s --help" 以取得更多資訊。` |
| `Report bugs to <%s>.` | `請向 <%s> 回報錯誤。` |
| `%s home page: <%s>` | `%s 首頁：<%s>` |
| `-?, --help  show this help, then exit` | `顯示這份說明，然後結束` |
| `-V, --version  output version information, then exit` | `輸出版本資訊，然後結束` |
| `cannot duplicate null pointer (internal error)` | `無法複製空指標（內部錯誤）` |
| `out of memory` | `記憶體不足` |

## R13 一致性與變更紀律

- R13.1 **最小改動**：正確且合規的譯文不重寫；每處修改只解決一個明確的問題。
- R13.2 分類：`term`（術語/句式）、`punct`、`space`、`align`、`wrap`、`semantic`、`new`、`none`。
- R13.3 不改寫已人工批准的行；異議寫入報告的「建議復議」。
- R13.4 改一處即改全部：固定句式或術語的變更覆蓋所有實例，跨元件相同英文保持相同。
- R13.5 證據：語義類改動引用源碼位置或語境；沒有把握寫疑問，不猜。
- R13.6 驗證先於交付：lint（含 `--msgfmt`）零 error；warning 逐條處理或說明理由。
- R13.7 不用正則批量替換代替逐條閱讀。
- R13.8（繁體專屬）**官方對齊條款**：官方五元件已譯的 msgid，以官方譯文為基準（R0.5）；我方認為官方有誤的（如 `Foreign-key constraints` → `外鍵檢查規則`），在報告中列出建議譯法並回饋上游，入庫時仍以對齊官方為先、例外須逐一記錄理由。
